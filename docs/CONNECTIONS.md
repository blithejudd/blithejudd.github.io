# Подключения

Раздел «კავშირები» доступен владельцу. Миграции, обе функции и интерфейс опубликованы в production 21.09.2026. Telegram остаётся выключенным до настройки владельцем; подробный статус — в STATE.md.

## Telegram и секреты

Владелец может заменить токен, получателя и соль хеширования, изменить список разрешённых Origin и включить/выключить заявки. Пустое поле сохраняет прежнее значение. Поля очищаются после запроса; сохранённые секреты не возвращаются в браузер. Статус содержит только признаки настройки и номер версии. Конкурирующее сохранение отклоняется.

Секреты хранятся в Supabase Vault. Таблица настроек и расшифрованное представление недоступны посетителю и браузерной роли владельца. Только service_role серверной функции получает runtime-секреты. SQL закрывает доступ browser-ролей ко всему vault в этом выделенном проекте; в общем проекте сначала проверьте зависимые приложения. Шифрование предоставляет [Supabase Vault](https://supabase.com/docs/guides/database/vault).

Кнопка проверки выполняет только getMe и getChat после проверки аккаунта и членства в portfolio_admins. Она не отправляет сообщение. Проверка доступности чата не гарантирует доставку будущей заявки. Реальная отправка выполняется только контактной формой при включённых заявках, после валидации и квот. Ошибки провайдера не пересылаются клиенту и секреты не логируются приложением.

## Production: отдельное развёртывание

1. Для нового проекта применить supabase/schema.sql. Для существующего настроенного проекта этот шаг пропустить.
2. Применить supabase/migrations/20260920_content_management.sql, затем supabase/migrations/20260921_connections.sql. Повторный запуск сохраняет настройки. Новое подключение Telegram выключено; соль создаётся автоматически. Старые переменные окружения Telegram не импортируются, токены не ротируются.
3. Развернуть обе Edge Functions вместе с общими модулями из репозитория:

```powershell
supabase functions deploy contact --no-verify-jwt
supabase functions deploy connections --no-verify-jwt
```

contact принимает публичные заявки. connections самостоятельно проверяет JWT через Auth и права владельца через RPC; отключение gateway JWT не делает административную операцию публичной. SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY предоставляет платформа.

4. Опубликовать статические файлы сайта отдельным действием. Владелец вводит новый токен/чат в панели, сохраняет и при необходимости явно проверяет. Разрешённые Origin теперь находятся в закрытых настройках, а не ALLOWED_ORIGINS окружения. Старые TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и CONTACT_HASH_SALT новая функция не читает.
5. Включить заявки только после готовности подключения. Публичный RPC возвращает только флаг contactEnabled. Автоматические локальные тесты ничего не разворачивают и настоящих сообщений не отправляют.

## Supabase: подготовка публичного подключения

Панель проверяет URL проекта, publishable/anon key, доступ владельца и необходимые таблицы/RPC. Для другого проекта требуются отдельные данные входа: JWT действующего проекта туда не передаётся. Пароль очищается, временный токен не сохраняется в хранилище браузера.

После проверки можно скачать js/config.js с публичными URL и ключом. Действующее подключение не переключается: файл нужно отдельно опубликовать. Данные, Storage, аккаунты, политики и секреты между проектами не переносятся. Флаг false в файле — совместимый безопасный fallback; после миграции состояние формы определяется серверной настройкой.

service_role, secret key и Management API token не принимаются этим редактором. Их назначение и путь управления показаны в панели: Supabase Dashboard для инфраструктуры проекта, локальная операторская настройка для Management API, GitHub и регистратор для Pages/DNS. Instagram и Google Fonts используют публичные ссылки, API-ключей у них нет. Allura хранится локально.

## Локальное демо и проверки

Запуск: node scripts/serve.mjs --cms-demo. Вход: demo@example.com / demo-password. Telegram принимает только demo-bot-token, demo-chat-id и необязательный demo-hash-salt. Реальные форматы секретов отклоняются. На диске сохраняются только признаки настройки, Origin и версия; проверки и заявки симулируются без внешней сети.

scripts/verify.ps1 проверяет валидацию, права, отсутствие секретов в ответах, запрет передачи активного JWT другому проекту и сохранение демо. tests/browser.mjs --demo проверяет интерфейс, очистку полей, явную проверку, экспорт конфигурации и включение/выключение формы. tests/migration.mjs исполняет SQL/RLS в PGlite с ролями посетителя, не-владельца, владельца и service_role, проверяет конфликт версий и повторный запуск. Только интерфейс Vault заменён заглушкой: шифрование реального Supabase этим тестом не проверено.
