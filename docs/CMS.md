# Управление содержимым

Вся панель и публичный интерфейс — на грузинском. Редактор управляет существующим дизайном, не принимает произвольный HTML, CSS или JavaScript.

## Что доступно владельцу

- **Фотографии:** название, описание, категория, порядок, публикация, замена изображения и удаление. Несохранённые поля соседних карточек сохраняются при любых операциях над другой карточкой. Перед обновлением списка и выходом с правками требуется подтверждение.
- **Загрузка:** число выбранных файлов и общее число фотографий программно не ограничены. Изображения обрабатываются последовательно при отправке. Реальные ограничения: память устройства, квоты/трафик Supabase, исходник до 20 МБ и 80 Мп, результат WebP до 8 МБ и 2400 px. Новые фото — черновики до включения публикации.
- **Категории:** добавление, название, порядок, видимость, удаление. Идентификатор стабилен, переименование не ломает фотографии. Используемую категорию БД удалить не разрешает; сначала нужно переназначить фотографии. Скрытая категория и её фотографии исключаются из публичных запросов. Категории автоматически появляются в фильтрах и форме заявки.
- **Содержимое:** тексты меню, главного экрана, биографии, услуг/цен, контактного раздела, подвала, метаданных; описания изображений и доступные названия; внешние HTTPS-ссылки. Разделы сгруппированы, есть поиск поля. Переносы и выделения существующего дизайна сохраняются: каждый текстовый фрагмент редактируется отдельно.
- **Изображения:** главная фотография, биография, изображение для социальных сетей; загрузка замены и центр кадра. Можно скрыть/переставить разделы и отдельные услуги. Латинская подпись сохраняет шрифт Allura.
- **Публикация:** отдельные кнопки сохранения приватного черновика, его просмотра, публикации и возврата черновика к опубликованной версии. Фото и категории сохраняются отдельно от документа содержимого. Конфликт параллельного редактирования документа определяется по номеру версии и не перезаписывает чужие изменения молча.

Системные сообщения форм остаются грузинскими; введённые владельцем тексты не переводятся автоматически. Статические технические настройки (ключи, домен, включение Telegram, политика безопасности) не предоставляются посетителям через редактор.

GitHub Pages отдаёт статический HTML: CMS обновляет метаданные в браузере. Социальные роботы, которые не выполняют JavaScript, продолжают видеть исходные метатеги HTML; для обновления их карточек нужны также изменения статического HTML и публикация.

## Рабочий локальный демонстрационный режим

```powershell
node scripts/serve.mjs --cms-demo
```

Открыть `http://127.0.0.1:4173/admin/`. Демоданные входа: `demo@example.com` / `demo-password`, поля заполнены автоматически. Сайт: `http://127.0.0.1:4173/`.

Демо использует ту же панель и REST-клиент, но отдельный loopback backend, не Supabase. Данные сохраняются в игнорируемых `test-results/cms-preview.json` и `test-results/cms-preview-assets/`, переживают перезапуск. Видимый баннер отличает демо от production. Демо-учётные данные не подходят для настоящего сайта; изменение пароля в демо недоступно. Telegram не отправляется. Без `--cms-demo` сервер использует обычный `js/config.js`. Секреты не копируются в демо.

## Порядок подключения production (выполнено 21.09.2026)

1. В уже настроенном проекте выполнить `supabase/migrations/20260920_content_management.sql` через SQL Editor. Для совершенно нового проекта сначала выполнить `schema.sql`, затем эту миграцию. При повторном запуске базовой схемы снова применять CMS-миграцию последней: она уточняет публичную политику фотографий.
2. Затем применить миграцию подключений и развернуть обе функции по `docs/CONNECTIONS.md`. Для Telegram используются обновлённые `supabase/functions/contact/index.ts` и `validation.js`. Сервер проверяет выбранную категорию в БД и передаёт её грузинское название. До этого не включать форму для новых категорий.
3. После отдельного решения о публикации разместить обновлённые HTML/CSS/JS на GitHub Pages. Публичные ключи в `js/config.js` остаются прежними. Новые `content.js`, `cms-admin.js`, `confirm.js`, `forms.js` входят в публикацию вместе с остальными JS.
4. Проверить с настоящим владельцем сохранение черновика, публикацию, фото и категории. Никакие production-операции не выполняются локальными тестами.

Миграция не удаляет старые фотографии и не перезаписывает тексты. Пустой документ использует исходные тексты HTML. Повторное применение сохраняет данные. До применения миграции старый сайт работает, а панель показывает инструкцию для новых разделов. При сетевом сбое уже подключённого CMS сайт показывает ошибку, а не возвращает удалённые тексты/скрытые разделы.

## Хранение и доступ

`categories` защищена RLS, изменение доступно только `portfolio_admins`. `photos.category` — внешний ключ. `site_content` содержит две строки: `draft` и `published`; посетитель может прочитать только опубликованную. Сохранение выполняется с проверкой `revision`. Сервер ограничивает документ 1 МиБ, клиент — отдельный текст 5000 символами, центр кадра 0–100%, порядок 0–1000000.

Содержимое применяется через текстовые узлы/безопасные атрибуты, никогда через HTML-вставки. `data-content` в `index.html` — стабильные ключи; не перенумеровывайте их при будущих изменениях шаблона. Изменение структуры дочерних текстовых узлов требует переноса соответствующих ключей документа.

Bucket остаётся публичным: приватность черновика относится к данным, не к прямой ссылке изображения. Старые файлы при замене сохраняются, чтобы не повредить опубликованную версию и неопределённо завершившиеся запросы. Их можно удалить вручную после проверки отсутствия ссылок в опубликованном документе, черновике и фотографиях. Удаление фотографии сохраняет прежнее поведение: запись удаляется, затем её загруженный файл.

## Проверки

```powershell
./scripts/verify.ps1
node tests/browser.mjs
# При работающем локальном --cms-demo на 4173:
node tests/browser.mjs --demo

# Необязательный тест SQL в настоящем PostgreSQL/WASM без production:
npm install --prefix test-results/sql-check --no-save --package-lock=false --ignore-scripts @electric-sql/pglite@0.5.8
node tests/migration.mjs
```

PGlite нужен только этому тесту, не сайту и не сборке. Тест исполняет исходную схему/миграцию, проверяет повторный запуск, RLS посетителя/не-владельца/владельца, приватность черновика, скрытые категории, FK и конфликт версий. Заглушены только инфраструктурные таблицы Auth/Storage Supabase; настоящий развёрнутый Supabase/Telegram это не заменяет.


Публичные контакты: в разделе «კონტაქტი» поле телефона принимает 7–15 цифр с необязательным + и пробелами/скобками/дефисами; поле Instagram принимает @имя или HTTPS-ссылку на профиль. Контакты внизу сайта используют тот же черновик/предпросмотр/публикацию. Пустой телефон скрывается; пустой Instagram скрывает все связанные ссылки. Существующая ссылка Instagram сохранена как исходное значение, телефон изначально пустой. Отдельная миграция для этих полей не требуется.

## Редактор для владельца

Панель разделена на «მთავარი» (главная), «ფოტოგრაფის შესახებ» (о фотографе), «სერვისები და ფასები» (услуги), «კონტაქტები» (контакты) и тексты портфолио. Фото, категории и подключения остаются отдельными экранами. SEO, меню, подписи формы, accessibility и порядок разделов находятся в «დამატებითი პარამეტრები». Поля сгруппированы в карточки, названия описывают назначение, а не повторяют текущий текст. Существующие ключи CMS не изменены.

Прямая ссылка на контакты: http://127.0.0.1:4173/admin/#contact. После входа сразу открывается этот экран; телефон и Instagram находятся в первой карточке. На узком экране раздел выбирается в списке «განყოფილება», для контактов также есть отдельная кнопка. Переключение разделов сохраняет введённые значения в форме. Кнопки сохранения/предпросмотра/публикации применяют все текущие изменения редактора, не только видимую страницу; это явно указано рядом с кнопками.

`node tests/admin-editor.mjs` требует запущенного локального демосервера. Проверяет настоящий демо backend: прямой вход/мобильную навигацию, ошибочный URL без сохранения, черновик, предпросмотр, публикацию, tel/Instagram и скрытие пустых контактов. После проверки восстанавливает исходные значения черновика и публикации с контролем конкурентных изменений; версии строк увеличиваются. Production этот сценарий не использует.
