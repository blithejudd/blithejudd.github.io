ინსტრუქცია იხილეთ პროექტის README ფაილში. აქ არ განათავსოთ საიდუმლო service_role გასაღები.

Supabase — მონაცემები, ფოტოები და შესვლა

მოქმედი პროექტი:

ეს საჯარო პარამეტრები საიტის საწყის ფაილშია. ჯერ მოწმდება ახალი კავშირი და მფლობელის უფლება, შემდეგ მზადდება config.js. ჩამოტვირთვა მოქმედ საიტს არ ცვლის: ფაილი უნდა განათავსოთ js/config.js-ის ნაცვლად და გამოაქვეყნოთ საიტი. სხვა პროექტზე გადასვლამდე გადაიტანეთ მონაცემები, ფოტოები, მომხმარებლები და მიგრაციები.

სხვა პროექტისთვის საჭიროა მისი მფლობელის ანგარიში. მიმდინარე სესია სხვა მისამართზე არ იგზავნება; პაროლი არ ინახება.

config.js-ის ჩამოტვირთვა
სერვერული და ჰოსტინგის გასაღებები

Supabase service-role / secret გასაღები გამოიყენება მხოლოდ სერვერზე. მისი შექმნა ან როტაცია ხდება Supabase-ის API Keys განყოფილებაში; პლატფორმის სერვერული გარემო განაახლეთ იქვე. აქ მისი შეყვანა ან შენახვა დაუშვებელია.

Management access token მხოლოდ ლოკალურ ადმინისტრაციულ სკრიპტებს სჭირდება. ის იმართება Supabase ანგარიშის Access Tokens განყოფილებაში და საიტის პანელს არ გადაეცემა.

GitHub Pages-ის გამოქვეყნება და დომენის DNS იმართება GitHub-სა და დომენის მომწოდებელთან. GitHub-ის პირადი ტოკენი ამ საიტს არ სჭირდება. Vault-ის დაშიფვრის გასაღებს მართავს Supabase.

შესვლის პარამეტრები — პაროლის შეცვლა

პირველი შესვლის შემდეგ შეცვალეთ დროებითი პაროლი. დროებითი ელფოსტა მხოლოდ შესასვლელი სახელია და წერილებს ვერ მიიღებს. ნამდვილი ელფოსტის დასაკავშირებლად გამოიყენეთ Supabase-ის Authentication → Users განყოფილება; დროებითი მისამართით პაროლის აღდგენა შეუძლებელია.

წაიშალოს ფოტო?

ფოტო გაქრება პორტფოლიოდან. ატვირთული ფაილი წაიშლება საცავიდან. ამ მოქმედების გაუქმება შეუძლებელია.

გსურთ გასვლა?

შეუნახავი ცვლილებები და აუტვირთავი ფოტოები დაიკარგება. შენახული მონახაზი დარჩება.
